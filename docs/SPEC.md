# Kiln 언어 스펙 v0.2 (확장자 `.kl`)

> 상태: 초안. 열린 결정 없음 (13절 참고).

## 0. 설계 원칙

- C 수준 의미론(수동 메모리, 포인터) + Rust풍 문법
- 암시적 변환 없음. 모든 변환은 `as`로 명시
- 표현식 지향 (`if`, `match`, 블록이 값을 가짐)
- 상속 없음, 합성 우선
- GC, 클로저 없음
- 대상: x86-64 Linux (System V ABI) 먼저, ARM64(AAPCS64)는 이후

## 1. 어휘

- 주석: `// ...`, `/* ... */`
- 키워드: `fn let mut struct enum impl match if else while loop break continue return extern const as true false null sizeof Self static`
  - `static`은 예약어. M3 이전에는 파서가 "미지원" 에러를 냄
- 구두점 중 특수 토큰: `...` (extern 가변 인자), `_` (와일드카드 패턴)
- 식별자: 연속 밑줄 `__`를 포함할 수 없음 (생성 심볼 `Type__method`와의 충돌 방지). 단, `extern` 선언의 이름은 예외
- 정수 리터럴: `42`, `0xFF`, `0b1010`, `1_000_000`
- 부동소수 리터럴: `1.5`, `2.0e-3`, `3.` 불허 (소수점 뒤 숫자 필수)
- 문자 리터럴: `'a'` (타입 `u8`)
- 문자열 리터럴: `"hello\n"` (타입 `*u8`, NUL 종료, `.rodata`에 배치)
- 이스케이프 (문자·문자열 공통): `\n \t \r \0 \\ \' \"`, `\xNN` (바이트 값 00–FF)
- 불리언: `true`, `false`

## 2. 타입

| 분류 | 타입 |
|---|---|
| 정수 | `i8 i16 i32 i64 isize`, `u8 u16 u32 u64 usize` |
| 부동소수 | `f32`, `f64` (IEEE 754) |
| 기타 | `bool`, `()` (unit) |
| 포인터 | `*T` |
| 배열 | `[T; N]` (N은 컴파일 타임 상수) |
| 사용자 정의 | `struct`, `enum` |

- `isize`/`usize`는 포인터 크기 (64비트)
- `()`는 값 없는 블록/함수의 타입. 반환 타입 생략 시 `()`

## 3. 타입 변환

암시적 변환은 없다. 정수와 정수, 정수와 실수 사이도 예외 없음.

```
let a: i32 = 5;
let b: i64 = a as i64;      // 부호 확장
let c: f64 = b as f64;
let d: f32 = c as f32;
```

`as` 허용 목록:
- 정수 ↔ 정수: 확장(부호/제로), 절단
- 정수 ↔ 실수
- `f32` ↔ `f64`
- 포인터 ↔ 포인터, 포인터 ↔ `usize`
- `bool` → 정수 (0/1)

실수 → 정수 캐스트에서 범위 밖/NaN 값의 동작은 미정의 (`cvttsd2si` 직접 사용, 포화 캐스트는 나중에 옵션으로 검토)

리터럴 규칙:
- 정수 리터럴은 기대 타입이 있으면 그 타입, 없으면 `i32`
- 실수 리터럴은 기대 타입이 있으면 그 타입, 없으면 `f64`
- 이항 연산: 리터럴이 아닌 피연산자를 먼저 검사하고, 그 타입을 리터럴 쪽의 기대 타입으로 사용. 양쪽 다 리터럴이면 바깥 기대 타입, 그것도 없으면 위 기본값. `null`도 같은 규칙 (`p == null`)
- 정수 리터럴이 대상 타입의 범위를 벗어나면 컴파일 에러 (`let a: u8 = 300;`, `let b: i8 = 0xFF;`, `let c: u8 = -1;` 모두 에러)
- 단항 `-` 바로 뒤의 정수 리터럴은 음수 리터럴 하나로 합쳐 범위를 검사 (`let m: i64 = -9223372036854775808;` 허용)
- 비트 패턴이 필요하면 `0xFF as i8`처럼 명시

## 4. 연산자

- 산술: `+ - * / %` (`%`는 정수 전용. 실수는 라이브러리 `fmod` 사용)
- 비트: `& | ^ ~ << >>` (`>>`는 부호 있는 타입이면 산술, 없으면 논리)
- 비교: `== != < <= > >=`
- 논리: `&& || !` (단락 평가)
- 포인터: `&x`(주소), `*p`(역참조), `p + n`(요소 단위), `p - q`(요소 개수, `isize`), `p[i]`
- 대입: `=` 및 복합 대입 `+= -= *= ...`
- 우선순위: Rust와 동일 계열 (단항 > `as` > 곱셈류 > 덧셈류 > 시프트 > `&` > `^` > `|` > 비교 > `&&` > `||` > 대입)
- 비교 연산자는 비결합. `a < b < c`는 파싱 에러

동작 정의:
- 정수 오버플로: 2의 보수 wrap (정의됨)
- 부호 있는 `/`는 0 방향 절단, `%`의 부호는 피제수를 따름 (`idiv`와 동일)
- 정수 0으로 나누기, 부호 있는 `MIN / -1`과 `MIN % -1`: 미정의 (하드웨어 트랩)
- 시프트 양이 비트 폭 이상: 미정의
- 실수 비교: IEEE 규칙 (NaN과의 비교는 `!=` 제외 모두 false)

## 5. 표현식과 문장

- 블록 `{ ... }`의 값은 마지막 표현식. 끝에 `;`가 있으면 `()`
- `if`/`else`, `match`는 표현식. `if`에 `else`가 없으면 전체 타입은 `()`이고 본문 타입도 `()`여야 함 (발산하는 본문은 허용)
- `while cond { }`, `loop { }`, `break`, `continue`, `return`
- 블록형 표현식(`if` `while` `loop` `match` `{}`)이 문장 위치에 오면 `;`를 생략할 수 있음. 이때 그 타입은 `()`여야 함
- `if`, `while`, `match`의 헤드(조건/스크루티니)에서는 구조체 리터럴을 쓸 수 없음. 괄호로 감싸면 허용: `if p == (Point { x: 0.0, y: 0.0 }) { ... }`
- `let x = expr;` 는 기본 불변, `let mut x = expr;` 로 가변
- 불변성은 이름을 통한 재대입만 금지함. `&x`는 불변 변수에도 허용되며, 포인터를 통한 쓰기는 제한하지 않음
- 모든 `let`은 초기화 필수 (미초기화 변수 없음)
- 섀도잉 허용 (같은 스코프, 하위 스코프 모두)
- `return`, `break`, `continue`는 어떤 타입과도 합쳐지는 "발산" 표현식. 타입 검사기 내부 전용 never 타입으로 처리하고 사용자 문법으로는 노출하지 않음
- 최상위 선언(`fn` `struct` `enum` `impl` `const` `extern`)은 순서 무관. 선언 수집 패스 후 본문 검사 패스

```
let sign = if x < 0 { -1 } else { 1 };
```

## 6. 구조체와 메서드

```
struct Point { x: f64, y: f64 }

impl Point {
    fn new(x: f64, y: f64) -> Point {
        Point { x: x, y: y }
    }
    fn norm2(self: *Point) -> f64 {
        self.x * self.x + self.y * self.y
    }
}

let p = Point::new(3.0, 4.0);
let n = p.norm2();
```

- 필드 접근은 값/포인터 모두 `.` 사용 (1단계 자동 역참조)
- 수신자 형태:
  - `self: *Self`: `p.f(args)`는 `Type__f(&p, args)`로 변환. `p`가 `*T`면 그대로 전달
  - `self: Self`: 값 복사로 전달. `p`가 `*T`면 자동 역참조 후 복사
  - `self`가 없는 연관 함수는 `Type::f(args)`로만 호출
- `Self`는 impl 대상 타입의 별칭
- 심볼 이름은 `Type__method` 형태로 평탄화 (맹글링 없음. 1절의 `__` 금지 규칙으로 충돌 방지)
- 레이아웃: 필드 순서 유지, 자연 정렬, 끝 패딩 (C 호환)
- 상속 없음

구조체 값 전달/반환 규약:
- 1차: 구조체는 항상 스택 메모리로 전달하고, 반환은 숨은 포인터 방식. `extern` 경계에서만 System V 분류 적용
- 이후(M5 이후 별도 마일스톤): 16바이트 이하 구조체를 레지스터로 넘기는 System V 분류를 내부 함수에도 적용

## 7. enum과 match

```
enum Shape {
    Circle(f64),
    Rect(Point, Point),
    Empty,
}
```

- 레이아웃: `u32` 태그 뒤에 페이로드. 페이로드 오프셋은 모든 페이로드 중 최대 정렬값에 맞추고, 크기는 최대 페이로드 크기
- 생성: `Shape::Circle(1.5)` (경로 필수)
- 패턴에서는 스크루티니 타입으로 variant 이름을 해석하므로 경로 생략 가능

```
fn area(s: *Shape) -> f64 {
    match *s {
        Circle(r) => 3.14159 * r * r,
        Rect(a, b) => (b.x - a.x) * (b.y - a.y),
        Empty => 0.0,
    }
}
```

1차 패턴: variant(바인딩 포함), 정수/불리언 리터럴, `_`, 변수 바인딩
- 대문자로 시작하는 식별자 패턴은 반드시 variant. 해당 variant가 없으면 컴파일 에러
- 소문자로 시작하는 식별자 패턴은 변수 바인딩
- 완전성 검사 필수. 빠진 경우 컴파일 에러 (누락된 variant 이름 표시)
- 도달 불가 arm은 컴파일 에러
- 바인딩은 값 복사 (소유권 개념 없음)
- 중첩 패턴은 2차

## 8. 타입 추론 (1차 범위)

- 대상은 지역 변수 `let`만. 함수 시그니처, 구조체 필드는 항상 명시
- 방식: 초기화식의 타입 사용 + 리터럴은 기대 타입 전파 (양방향 경량 방식, 3절 리터럴 규칙 참고)
- 전면 Hindley-Milner 스타일 추론은 하지 않음
- 근거: 구현이 단순하고 에러 메시지가 명확함

## 9. 메모리

- `malloc`/`free`는 `extern`으로 선언해 사용
- 내장 `sizeof(T)` (타입 인자를 받는 키워드 연산자)
- 배열은 값 타입. 범위 검사 없음 (C식). 배열에서 포인터 자동 변환 없이 `&a[0]`으로 명시
- `null`은 기대 타입이 `*T`일 때 유효한 리터럴
- 문자열 리터럴(`.rodata`)을 통한 쓰기는 미정의
- 전역: `const NAME: T = 상수식;` (스칼라 상수). 가변 전역 `static`은 M3 이후 추가 (`.data`/`.bss`, 재배치 학습)

## 10. FFI와 ABI

```
extern fn printf(fmt: *u8, ...) -> i32;
extern fn malloc(n: usize) -> *u8;
```

- `extern` 경계는 항상 System V AMD64 ABI를 따름 (C를 호출하고 C에서 호출 가능). 내부 함수도 최종적으로 SysV 준수가 목표이며, 구조체 값 전달은 6절의 단계 계획을 따름
- 가변 인자 호출 시 `al`에 사용한 벡터 레지스터 수를 설정
- `f32`를 가변 인자로 넘길 때는 `as f64`로 명시 승격 (암시적 승격 없음)
- 진입점: `fn main() -> i32`

## 11. 부동소수점 세부

- 타입: `f32`, `f64`
- x86-64: SSE2 스칼라 명령 (`addsd`, `mulss` 등), 레지스터 `xmm0`~`xmm15`
- System V: 실수 인자 `xmm0`~`xmm7`, 반환 `xmm0`. 모든 `xmm`은 caller-saved (callee-saved 없음)
- 실수 리터럴은 `.rodata` 상수 풀에 배치
- 비교는 `ucomis*` + 플래그 처리 (NaN의 parity 플래그 주의)
- IR 값에 처음부터 "레지스터 클래스"(정수/실수)를 구분해 두고, 레지스터 할당기는 클래스별로 동작
- ARM64: 스칼라 FP 명령(`fadd`, `fmul` 등), `v0`~`v7`로 인자 전달

## 12. 마일스톤

| 단계 | 내용 |
|---|---|
| M1 | 정수/bool, 함수, 제어 흐름, `extern printf` → 어셈블리 출력 (IR 경계는 이 단계부터 유지) |
| M2 | 포인터, 배열, 구조체, 메서드 문법 |
| M3 | `enum`/`match`, 지역 변수 타입 추론 |
| M4 | 부동소수점 (SSE), 레지스터 클래스 분리 |
| M5 | SSA IR 정비, 최적화 패스(상수 전파, 죽은 코드 제거, mem2reg), 선형 스캔 레지스터 할당 |
| M6 | 직접 ELF 출력 (어셈블러/링커 제거) |
| M7 | 스펙 고정 → C++ 구현, 비교 글, 벤치마크 |
| 이후 | ARM64 백엔드 (Rust 구현에 추가, QEMU로 검증) |

2차 기능: 단형화 제네릭, 트레이트 + vtable, 중첩 패턴, 다중 파일/모듈 (M7 이후 논의)
제외: 상속, 클로저, GC

### 이후 검토할 파생 쟁점
- 대문자 규칙 때문에 `const`를 패턴에 쓸 수 없음. const 패턴 도입 시 "variant가 아니면 const 탐색"으로 확장
- `self: Self`는 큰 구조체에서 호출마다 복사 비용 발생 (의미상 문제 없음)
